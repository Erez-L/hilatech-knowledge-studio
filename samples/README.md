# Sample documents

Everything in this folder is **fictional sample content**. "Northstar Business Services" is an invented
company; its policies, prices, people and dates do not describe any real organization. Every document
says so in its own first lines.

## What is here

```
samples/
  northstar/
    en/   six documents, English edition
    he/   the same six documents, Hebrew edition
  evaluation/
    questions.json   evaluation question set (see evaluation/README.md)
```

| Document | Format | Structure |
| --- | --- | --- |
| `customer-support-handbook` | PDF | 12 pages, one numbered section per page |
| `refund-and-cancellation-policy` | PDF | 4 pages, one section per page |
| `product-and-service-catalog` | PDF | 6 pages; page 6 is a plan comparison table |
| `employee-onboarding-guide` | DOCX | headings 1 to 3 with sub-headings (1.1 … 3.2) |
| `remote-work-policy` | DOCX | five top-level headings |
| `holiday-schedule-2027` | TXT | plain text |

The two editions have the same file names, the same page and heading structure and the same business
facts (amounts, deadlines, dates). Plan names (Payroll Basic, Bookkeeping Essentials, Bookkeeping Growth)
are not translated. The remote work policy was written in Hebrew first; its English edition is a translation.
The other five were written in English first.

Loading both editions into one knowledge base gives every fact two sources, one per language. That is
intended for some tests and unwanted for others; see `evaluation/README.md`.

## Rebuilding

All twelve files are generated by one script. Do not edit them by hand.

```
pip install reportlab python-docx python-bidi     # plus the DejaVu Sans fonts (fonts-dejavu-core)
python3 scripts/build-sample-documents.py
pnpm exec tsx scripts/check-samples.ts            # from the repository root
```

The business facts are defined once at the top of the build script and used by both editions.
The English wording of the documents is asserted by the test suites (`packages/ai/test`,
`packages/core/test`), down to page numbers and section headings, so change it only together with the tests.
PDF and DOCX files contain a creation time, so a rebuild changes their bytes even when the text is the same.

`scripts/check-samples.ts` runs the application's own extractor over all twelve files and checks page
counts, the reading order of the Hebrew PDFs, that both editions carry the same numbers on every page
and in every section, and that every source named in `evaluation/questions.json` exists.

## Notes on the Hebrew PDFs

- A PDF stores glyphs in the order they are drawn, left to right. The build script wraps each Hebrew
  paragraph into lines itself and then reorders every line for display (Unicode bidi algorithm), which
  is what ordinary PDF producers do. The application's extractor (pdf.js through `unpdf`) turns each
  line back into logical order. This has been checked for these files only; it is not a general claim
  about Hebrew PDFs from other producers.
- The comparison table on page 6 of the Hebrew catalog is written column by column (labels first, then
  each plan with its values), while the English table is written row by row. Extracted text therefore
  differs in arrangement between the editions: English reads "Monthly price $180 $290 $640", Hebrew
  reads "Bookkeeping Growth $640 600 תנועות …". Both are complete.
- The fonts are DejaVu Sans, embedded as subsets.
